# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Fan site for "Trusty da Horse", a stick-figure horse drawn on notebook paper: static HTML pages (comics, browser games, an AI chat, a 3D viewer) plus Vercel serverless functions backed by MongoDB, and a Cloudflare Worker in `realtime/` that runs the online games (Trusty Fever's rooms, Trusty Blackjack's tables). There is no build step, bundler, framework or linter.

## Tests

- `npm test` (Node's built-in test runner, no browser; run `npm install` first) covers the pure modules (Trustle, the TV/radio schedule, the Draw grader, Trusty Fever and its online rooms, Blackjack's rules, solo game and online tables, click ranks and the daily bonus, the PNG decoder, the account rules), the click bank's request checks, the hand-written lists' rules from this file (fun fact length, Trustle words and their `see` links, Trustle's rewards and the page's table of them, the click ranks and daily bonus and the leaderboard page's list of them, lineups), the image rules (every image the site names exists, nothing loose in `images/`) and the auth endpoints' input checks. Tests live in `tests/*.test.js`; `tests/setup-env.js` points the database settings nowhere, so a test that reached a real query fails instead of touching data. The click bank's money tests need a real MongoDB, so they're skipped unless `BANK_TEST_MONGO_URI` points at a throwaway one (`tests/bank.test.js` says how; run them whenever `utils/bank.js` changes); the solo Blackjack game's MongoDB test (`tests/solo-blackjack.test.js`) is skipped the same way. Add a test when you add a rule here that code can check.
- `npm run smoke` loads every page in Chromium against `tools/dev-server.mjs` at phone and desktop widths, logged out and in, and fails on uncaught errors, console errors, missing files, sideways scrolling, broken images or links, and axe-core accessibility violations. It also has two people play a few seconds of online Trusty Fever (with a stake) and Blackjack for clicks (one player's hand on their own, then a hand at a table together), with the same checks on every online screen. Playwright is preinstalled in Claude Code cloud sessions. Run both before pushing a change to pages.

## Running locally

- Deployed on Vercel; `vercel.json` sets `outputDirectory: "."`, so the repo root is served as-is and every file in `api/` becomes a function at `/api/<path>` (e.g. `api/auth/login.js` → `/api/auth/login`). It also sends headers: `nosniff` everywhere, a `noindex` for `pages/games/embed/` (see **Search engines** below), a year of caching for `fonts/` (those files never change) and a day for `images/`, `sound/` and `models/` (so replacing an image in place can take a day to reach returning visitors: give a changed image a new name instead). Its `redirects` send the link-preview images' (`og:image`) addresses from before `images/` had folders to where they are now, since other sites keep those. `404.html` at the root is Vercel's not-found page.
- Full stack: `vercel dev` (needs `.env` with `MONGODB_URI`, `USERS_MONGODB_URI`, `JWT_SECRET`, `GEMINI_API_KEY`, `RESEND_API_KEY`, plus `FEVER_ROOMS_URL` and `FEVER_SECRET` for online Trusty Fever). Frontend only: `npm run dev:mock` (`tools/dev-server.mjs`) serves the site with a pretend API that answers every endpoint with sample data, so leaderboards, profiles and the Latest Update render; set the cookie `mock=in` plus the usual localStorage flag to be logged in (as an admin). It also runs the online rooms and tables itself (`tools/local-rooms.mjs`, the same `realtime/room.js` and `realtime/table.js`) with a pretend click bank that forgets everything on restart (`tools/mock-bank.mjs`; everyone starts with 12,345 clicks), and the cookie `mockuser=<name>` picks who you are, so two browsers can play each other. Any plain static server works too, without the API-backed parts.
- Pages must be served from the root — all asset, script and API paths are root-absolute (`/styles/...`, `/scripts/...`, `/api/...`).

## Shipping changes

- Claude Code sessions push finished work straight to `main` without asking: commit on the session's branch, push it, then fast-forward `main` to it (`git push origin HEAD:main`). If `main` has moved, merge it into the branch first. Never force-push `main`.
- `main` deploys to the live site, so check your change before pushing: run `npm test` and `npm run smoke` (see **Tests**), and look at the pages you touched.
- This doesn't apply to @claude on GitHub, which only pushes to `main` when explicitly asked (below).

## Frontend architecture

- **Design system:** `styles/stylesheet.css` holds tokens (paper/ink palette, Permanent Marker + Caveat fonts, self-hosted in `fonts/` with their licenses: the `@font-face` rules are at the top of the stylesheet and every page head preloads the two `-latin` files; new pages copy those two `<link rel="preload">` lines) and shared components: `.sheet` (ruled notebook paper), `.card`/`.card-link` (index cards with a stretched title link), `.sticky-note`, `.btn` variants, `.panel`, `.tabs`, `.board` (leaderboard rows), forms, dialogs. `.ink` makes black-on-white line art blend into the paper (`mix-blend-mode: multiply`). `styles/games.css` adds the game shell (`.stage` fixed-aspect play area with `--ar`/`--stage-room`, overlays, focus mode, touch pads) and is only linked from game pages.
- **Viewport heights:** size anything in the page flow (game stages and boards, the TrustyGPT chat box) with `svh`, not `dvh`. On phones `dvh` changes every time the browser toolbar hides or shows, so anything sized with it grows and shrinks while you scroll. `dvh` is right for fixed overlays that cover the screen (dialogs, the mobile menu, the comic reader, focus mode).
- **Shared chrome:** every page loads `scripts/site.js` (ES module) and uses `<trusty-header>` / `<trusty-footer>` custom elements, which render the nav, account area, mobile menu and the header "clicker" (`/api/clicks`). The nav list lives in `NAV` in `site.js`; an entry with `items` is a dropdown group (Games: Trustle, Flappy, Trustis, Draw Trusty and Leaderboards, under the games page; Trusty Media: Trusty TV and Trusty Radio, with its own page at `pages/media.html`; Trusty Tools: TrustyGPT, 3D Trusty, Trusty Weather, with its own page at `pages/tools.html`) that opens on hover or from its caret button in the header, and is listed indented in the mobile menu.
- **Click ranks and the daily bonus** (rules in `scripts/milestones.js`, pure functions shared by the header, the leaderboard, profiles, `api/clicks.js` and the pretend API): `RANKS` names the milestones a click total passes, from Foal at 100 to Trusty Himself at 1,000,000. The ring around Trusty's face in the header clicker fills up toward the next rank (`rankProgress`, set as `--progress`), its tooltip says how far that is, and reaching a new rank gets a "Rank up!" sticky note under the clicker and a spin, once per rank per device: `trusty:rank` remembers the highest one shown (so winning back clicks lost on a bet doesn't count again) and `trusty:rank:owner` whose it is (a different account starts over; it's in `LS_NAME_KEYS`, so a rename doesn't). The first time a device sees a player, the note just says which rank they're at. The notes are `aria-hidden` decoration; a `role="status"` span in the header says the same thing to screen readers. The clicks board shows each player's rank as a badge under their name (`rankBadge()` in `scripts/leaderboard.js`, colored by `rankLevel`), the board's note on `pages/leaderboard.html` lists every rank (`#rank-table`) and explains the daily bonus (`#daily-rule`), and `tests/milestones.test.js` checks both match the module, so change them together. The daily bonus (`DAILY`): the first click of each day (midnight Eastern, like Trustle) pays 25, plus 5 for every day in a row before it, up to 100. `api/clicks.js` pays it with the click itself (no separate request): `daily: { day, streak }` on the account's `click_game` document says which day was last paid, and the bonus only goes in if `daily.day` is still what the click read, so two tabs can't both collect it. A click's answer then has `daily: { added, streak }`; `GET /api/clicks` says whether today's is still waiting (`daily: { ready, streak, next }`), which the clicker shows as a "+25" tag on Trusty until it's clicked. Like Trustle's, these clicks are decided by the server only.
- **Session:** client login state is the `localStorage` keys `isUserLoggedIn` / `username` (the same keys the site has always used), plus `trusty:admin` for admins (`session.isAdmin`; it only shows the Admin button). `site.js` only calls `GET /api/auth/login` when the flag is set, clears it on 401, and exposes `session`, `sessionReady`, `onSession`, `sessionExpired` (call it when a protected API answers 401), `sessionRenamed` (after a username change), `logout`, `loginHref` (adds a `?next=` return path), `announceClicks` (clicks earned on the page) and `announceBalance` (the click bank's exact total after a bet, which can go down; the header clicker otherwise only ever moves up). `html[data-auth="in"|"out"]` plus `data-auth-show="in|out"` toggles logged-in/out content in markup.
- **Rendering user data:** build DOM with `h()` from `site.js` (never `innerHTML` with API data). Leaderboard names and drawings come from other users; `scripts/leaderboard.js` renders all the boards and only accepts drawings that are PNG data URLs.
- **Modules:** `scripts/leaderboard.js` (fetch/render the clicks, Flappy, Draw and Trustis boards (`BOARDS`) + drawing viewer), `scripts/milestones.js` (click ranks and the daily bonus, above), `scripts/comics.js` (season pages list episodes as cards with `data-episode`/`data-pages`; this turns them into a `<dialog>` reader with `#ep-N` deep links), `scripts/auth.js` (login/register/forgot/reset forms), `scripts/draw-reference.js` (Trusty's reference pose — Draw Trusty grading depends on it), `scripts/game-kit.js` (sprites, ink conversion, sound with a site-wide mute, focus mode, swipe input, local best scores), `scripts/rooms.js` (the online games' connection: room links, tickets, reconnecting, the player's click bank status).
- **Adding a comic episode:** drop pages at `images/comics/<comic>/<season>/e<N>/p<M>.jpg`, make the card's cover from page 1 (`convert p1.jpg -resize 640x -quality 78 cover.webp` in that folder, ImageMagick) and add an `<article ... data-episode="N" data-pages="M">` card to that season page whose image is that `cover.webp` with its real width and height. The reader opens the full-size JPEGs.
- **Images:** `images/` keeps every picture in a folder for what it is, with nothing loose at the top: `icons/` (the favicons and home-screen icon, whose Trusty face also shows up around the site), `trusty/` (Trusty himself: classic, detailed, seahorse, 3D, and TrustyGPT's photo), `thumbnails/` (each game's card picture, named after the game, like `flappy.webp`, plus Trusty Media's TV and Radio cards), `sprites/` (what the games draw: Snake's pieces and food, Trustis's blocks) and `comics/` (below; Season 2's missing poster photo is in `comics/datractorcrew/s2/`). Pages use WebP copies (`trusty/trusty-v2.webp`, `trusty/trusty-v2-176.webp` for small spots like the footer, thumbnails at 800px for game cards, and so on); the original PNGs/JPGs stay for `og:image` (link previews) and games that load them. Moving or renaming an image changes its address: update everything that names it (`tests/images.test.js` checks every image a page, script, stylesheet or API names is there), and if it's a link preview, add a redirect from the old address in `vercel.json`. A new image goes in as WebP sized for where it's shown (about twice its displayed width), with `width`/`height` attributes, `loading="lazy"` unless it's on screen when the page opens, and `fetchpriority="high"` on the first big one.
- **Layout shift:** anything a script fills in after load holds its final height in CSS meanwhile (`:empty` rules for the Trustle board and keys, the Blackjack hand and the leaderboard podium; `.page-state` for pages that swap between loading, message and content states), so the page doesn't jump. Keep that up when you add a part that's built by a script.
- **Latest Update box** (`.hero-note` in `index.html`): admins change it on the home page with the note's **Edit update** button, which turns the note into a form for the date (with a Today button), an optional bold headline and the message (plain text, cleaned like bios by `cleanText` in `utils/text.js`; at most 60 characters for the headline and 400 for the message). It comes from `utils/update.js`, served as `?action=update` on `api/leaderboard.js` to save a function slot: GET is public (`{ date, headline, text }`), POST checks `isAdmin` on the server. Every save is kept in the `updates` collection and the newest one is shown; until the first save it shows `DEFAULT`, the message that used to be written into the page. Vercel's CDN keeps the GET for a minute (`Vercel-CDN-Cache-Control`), so other visitors can get the old update for about a minute after a change; admins' pages add `&fresh=1` to skip the CDN and see their own changes right away. The page keeps the last update it got in `localStorage` (`trusty:update`) and shows it right away, so the note only waits for the API on a first visit.
- **Fun fact of the day:** the speech bubble above Trusty at the top of the home page (`.fact`) shows one fact from `FACTS` in `scripts/facts.js`, a new one at midnight Eastern (same for everyone), in list order from `FIRST_DAY` and then around again. They're real facts that are obscure and detailed: genuinely interesting, not the usual fun-fact-list trivia and not written to be funny, with horse ones mixed in. Check that a fact is true before adding it. Only add facts at the end, and keep each one to `MAX_LENGTH` (360 characters): the bubble sits above him on every screen size, and longer facts push the page title off the first screen on phones.
- **Trusty TV** (`pages/tv.html`, styles in `styles/tv.css`) is a pretend live TV with no server. `scripts/tv-lineup.js` lists YouTube links with their exact lengths and groups them into `CHANNELS` (Trusty TV on 21, SNN on 22, SpongeBob on 23); the channel knob flips through them and the page's `#key` hash picks one, and `scripts/tv-schedule.js` (pure functions) works out from the clock what's airing and how far in, so every viewer sees the same moment. Each run through a lineup is shuffled with a seed from its run number, so the order changes every time but is the same for everyone; when a run starts over, a video never comes back until at least `MIN_GAP` other shows have aired (it can be at most half the lineup, rounded down, not counting one show). The page corrects a wrong device clock with the site's `Date` response header. Logged-in viewers earn 5 clicks for every 5 seconds a show is playing on screen (paused, static and hidden tabs don't count): the page calls `POST /api/clicks?action=tv` with `{ channel: <key> }`, which allows one reward per 5 seconds per account (`lastTvReward`) and adds those 5 seconds to the account's watch time for that channel (`tvSeconds.<key>` in `click_game`, used for the profile's favorite channel), and tells the header clicker through `announceClicks()` in `site.js`. Lengths must be right, or shows get cut off or leave dead air; the page logs a console warning when one is off.
- **Trusty Radio** (`pages/radio.html`, styles in `styles/radio.css` on top of `styles/tv.css`, whose knobs, sound cue and sidebar it reuses) is Trusty TV as a wooden tabletop radio: same YouTube player, same clock schedule (`scripts/tv-schedule.js`), no server, no click rewards. Stations are in `STATIONS` in `scripts/radio-lineup.js` (key, frequency on the 88–108 dial, lineup); the presets and the tuning knob switch between them and the `#key` hash picks one. Trusty FM (102.1, `FM_LINEUP`) plays every Lil Peels song (all five albums from the artist's YouTube channel) plus a couple by other artists; SpongeBob FM (106.7, `SPONGEBOB_FM_LINEUP`) plays the show's production music from a YouTube playlist, with songs uploaded twice kept once and ones that won't play embedded left out; a station with no songs shows "Off the air". YouTube's rules apply as on Trusty TV: the video stays visible in the radio's window (no hidden or audio-only player), nothing covers it, it's at least 200×200 (`.radio-screen` min-height), and it only autoplays once half of it is on screen. It's under Trusty Media in the header nav, next to Trusty TV.
- **Trusty Weather** (`pages/weather.html`, styles in `styles/weather.css`, plus a full-width card at the top of the home page's teasers) is Trusty's local forecast, with no server. `scripts/weather.js` does everything: it only asks for the location from a tap, keeps the rough spot in `localStorage` (`trusty:weather:spot`) so it never asks again, re-detects it silently whenever the browser already allows it, and gets the forecast from Open-Meteo and the town name from BigDataCloud (both free, no key, called from the browser). There's deliberately no way to type or change the location. Trusty's lines are written pools in `weather.js` picked by date, so the home card and the page agree; after sunset he forecasts tomorrow.
- **Profiles** (`pages/profile.html?u=<username>`, styles in `styles/profile.css`; link to one with `profileHref()` from `site.js`) show a user's bio plus stats filled in from game data: member since (`createdAt`, or the `_id` time for old accounts), total clicks + rank with their click rank, how far the next one is and their daily bonus streak, Flappy best + rank, best current-grader Draw Trusty score + rank with the drawing, Trustis best + rank with that game's level and lines, Trustle stats from the synced history (`statsFrom`), favorite Trusty TV channel (the most `tvSeconds`, with watch time per channel), and how betting clicks went this month at Blackjack (solo and tables) and on Fever pots (`bank.stats` on the `click_game` document, only for games they bet on). With no `?u=` it shows your own. Leaderboard names and "Hi, name" in the header link to profiles. The data comes from `utils/profile.js`, served as `?action=profile` on `api/leaderboard.js` to save a function slot: GET `?u=` is public (case-insensitive name lookup, never returns email, `isMe` tells the page to show the edit button), POST `{ bio }` saves your own bio (plain text, max 300 characters) in the `profiles` collection. Snake/Blackjack/Fever bests are only in `localStorage`, so they're not on profiles. Your own profile also has **Change username** (below).
- **Username changes:** the rules for a new name are in `scripts/username.js`, shared by the sign-up form, `api/auth/register.js` and the profile page's Change username dialog: no spaces (or invisible characters), no `@` (the login form tells emails from usernames by it), at most 32 characters. Names from before the rules keep working. The rename is `utils/rename.js`, served as `?action=rename` on `api/leaderboard.js` to save a function slot: POST `{ username }` refuses a name someone else has (ignoring capitals) and a second change within 90 days (`usernameChangedAt` on the account; old names are kept in `pastUsernames`). Admin accounts can't be renamed and nobody can take an admin's name, since `ADMINS` goes by name. The game collections keep a copy of each player's name, so a rename copies the new one into all of them (`NAME_COPIES` in `utils/rename.js`: add any new collection that stores a name there) and sets a new login cookie. Other devices still have a token with the old name: `GET /api/auth/login` checks the account's current name, copies it again and swaps the token, and `site.js` moves the device's Trustle and click rank owner keys along (`LS_NAME_KEYS`) so Trustle doesn't take the new name for someone else.
- **Admin panel** (`pages/admin.html`, styles in `styles/admin.css`, `noindex` and not linked anywhere public) is for the accounts in `ADMINS` in `utils/auth.js` (`carson` and `luke`, matched case-insensitively). Admins get a small Admin button under "Hi, name" in the header (in the menu, an "Admin panel" button next to Log out), and can edit the home page's Latest Update right on the note (above). It has two tabs: **Drawings** lists every current-grader Draw Trusty drawing, most reported first, tinted by report count (1 yellow, 2 pink, 3+ red outline), with Remove (deletes the drawing and its score) and Looks fine (clears its reports); **Usernames** lists every account, newest first, with names containing a word from `utils/bad-words.js` on top. Flagging only lists a name; the admin panel never renames or deletes accounts. Players report a drawing from the drawing viewer in `scripts/leaderboard.js` (once per account per drawing, never their own); the board and profile APIs send each drawing's `id` and `at` (when it was saved) for that. The API is `utils/moderation.js`; every admin request checks `isAdmin` on the server.
- **Header nav** shows in full from 1120px (1240px when logged in, for the clicker and name); below that it collapses into the menu. Check those widths if you add a nav link. The admin button sits under the name so it doesn't widen the row; keep it narrower than "Hi, name".
- **Search engines:** every public page has a `<link rel="canonical">` with its full `https://trustydahorse.com/...` address and an entry in `sitemap.xml`, which `robots.txt` points to. When you add a page, add both (the two lists should match); when a page's content changes, update its `<lastmod>`. The home page's address is `https://trustydahorse.com/`, and the site links to it as `/`, never `/index.html`, so Google sees one home page; `index.html` also has `WebSite` structured data (JSON-LD) that gives Google the site's name. Pages that shouldn't be in search results (the auth pages, admin, 404) have `<meta name="robots" content="noindex">` and stay out of the sitemap, and `vercel.json` sends the same as an `X-Robots-Tag` header for the third-party files in `pages/games/embed/`. Don't block a page in `robots.txt` to hide it: Google can't see the `noindex` of a page it isn't allowed to fetch, and can still list it. Profiles aren't in the sitemap and have no canonical, since one fixed address can't cover every `?u=`.

## Games

- Flappy, Draw, Snake, Trustis, Blackjack and Trusty Fever are self-contained in `pages/games/*.html` (inline module scripts); Trusty Fever's rules live in a module, below. Flappy's physics (800×600 world, gravity, pipe gap/speed/spawn, hitbox) is intentionally identical to the original so leaderboard scores stay comparable — don't tweak it casually. Those constants are per 60 Hz frame, so the simulation runs in fixed 60 steps/second (drawing interpolates between steps) to play the same on 120/144 Hz screens. A pencil scores when Trusty's middle passes its middle (as in Flappy Bird); resting on the floor is safe by design. Seahorse Trusty (20+ points) is a thin drawing in the middle of that same wide hitbox, so the box is drawn around him as a dashed outline; don't shrink it to fit the drawing, or scores past 20 stop being comparable.
- **Trusty Blackjack** is `pages/games/casino.html`. Where the layout stacks (≤960px) its controls sit under the table, so they only show what you can do right now, right under the cards: Deal between rounds, Hit/Stand/Double/Split during one, the insurance question when it's asked (`data-phase` on `#controls`, set in `render()`). `showTable()` scrolls the table and those buttons onto the screen together when a round starts or ends, when insurance comes up and when a split makes the table taller. On phones long hands overlap instead of wrapping, so the table doesn't grow mid-round. Keep new controls inside that scheme, or phone players are back to scrolling between the cards and the buttons. Every hand is for real site clicks (there's no pretend-money mode any more; logged-out visitors get a Log in note on the felt). By default you play **on your own**, dealt by the site's API (below), with no room server; the side panel's **Play with friends** (shown once the API says the online games are set up) opens or joins an online table instead, which takes over the same felt and controls until you leave it. `render()` draws both from one shape: a solo game is put in the shape of the table's `{ t: 'table' }` message (`currentTable()`). The card maths for both is `scripts/blackjack.js`, and both deal on a server: a game dealt in the browser could be rigged to win clicks, so never add one back.
- **Trusty Blackjack on your own** (`utils/solo-blackjack.js`, `?action=blackjack` on `api/leaderboard.js`; the game itself is `utils/solo-blackjack-game.js`, with no database, so `tools/dev-server.mjs` and the tests play the same game with games in memory). Each move is a request: GET is the game as it stands (plus your clicks, limits and stale refunds from the bank), POST `{ do: 'deal', amount }`, `{ do: 'insure', take }` or `{ do: 'hit' | 'stand' | 'double' | 'split' }`. The shoe and the round are kept in `blackjack_solo` (one document per account, deleted after 30 days untouched) and the page only gets `view()`, so Trusty's hole card stays hidden. Trusty plays his whole turn inside the move that ends yours, and the page turns his cards over one at a time. Bets go through the click bank directly (the same `stake`/`settle` the room server's signed requests use): staked before they count, settled when the hand is over, and a payout that didn't get through is retried on the next request (the bank only pays a bet once). No clocks: a hand left for an hour is stood and settled on the next visit, before the bank's 2-hour refund of open bets. Two tabs: every save checks the document's version `v`, and a move that lost the race gets its stake back.
- **Trusty Blackjack for clicks:** a logged-in player opens a table (a code and a link, `casino.html#table=KXQT`, like Fever's rooms) or joins one; up to 5 people play against Trusty with their real site clicks. The table is `realtime/table.js` (one Durable Object per code, next to Fever's rooms): it deals from a shoe nobody else sees (Trusty's hole card stays face down in what players get), runs the hand with the rules in `scripts/blackjack.js` (`deal`, `insure`, `hit`/`stand`/`double`/`split`, `dealerStep`, `payouts`, all plain data so the tests can rig the cards), and times everyone: once someone bets, the others get 12 seconds; 12 seconds for insurance and 25 per hand (then it stands for you); a player who gets up mid-hand is stood for, and their bets still settle; nobody betting for 10 minutes gets them up from the table, so a forgotten tab can't keep a table (and Cloudflare's meter) running. Bets are 10 to 500 in tens (`BETS` in `scripts/blackjack.js`, so 3:2 and insurance come out in whole clicks). Every bet, double, split and insurance is staked at the click bank before it counts, and each hand is settled there (below). The page shows the others' hands smaller above yours, a countdown kept out of the screen reader's status line, and the table's code, people and a Copy link in the side panel.
- **Betting clicks: the click bank** (`utils/bank.js`, `?action=bank` on `api/leaderboard.js`). Clicks are the header clicker's total in `click_game`; every bet and payout is one atomic update of that document (open bets sit in `bank.open.<betId>` until settled), so two tabs or a retried request never spend the same clicks twice or pay twice. Only the server can stake or pay out: the solo Blackjack game calls it directly, and the room server signs each request with `FEVER_SECRET` (`signPayload` in `utils/fever-ticket.js`, `signedOp` in `utils/bank-rules.js`, which also has the limits and checks every value). Limits (`LIMITS`): at most 500 on one bet, and once a player is 5,000 down or 5,000 up for the day (Eastern time, like Trustle; open bets count as lost), no more bets until midnight. Blackjack payouts are capped at 3 times a bet; a Fever pot is added up by the bank itself from what it holds and written down in `fever_pots` (deleted after 30 days) so a retried payout pays the same. Bets nobody settles (a table that went away) go back to the player after 2 hours, on their next visit (the bank's GET). Don't sell clicks or let players send them to each other: that's what keeps this play money.
- **Draw Trusty grading** lives in `scripts/draw-grader.js` (pure JS, no DOM) and grades against the shapes in `scripts/draw-reference.js`. The browser grades for instant feedback, and `api/draw-api.js` re-grades the submitted PNG (decoded by `utils/png.js`) with the same module and stores its own score, so client-sent scores are ignored. Scores are tagged with `GRADER_VERSION`; leaderboard and personal-best queries only count the current version. If you change grading behavior, bump `GRADER_VERSION` so old and new scores don't mix.
- **Trustis** follows the standard Tetris Guideline: 10×20 field with hidden rows above, 7-bag, SRS rotation and wall kicks, hold, 5-piece next queue, guideline gravity/scoring (T-Spins, back-to-back, combos, perfect clears) and 0.5s lock delay with 15 move resets. The blocks come from `images/sprites/trustis.png`; `ART` in the page records which rotation state each drawing was made in (L and J art is vertical), and every cell's sprite turns with the piece so the drawing stays whole. Rotating the O only turns its drawing — it never moves or resets the lock delay, as in standard Tetris. When a logged-in player beats their best, the page sends `{ score, lines, level }` to the Trustis leaderboard (`utils/trustis.js`, served as `?action=trustis` on `api/leaderboard.js` to save a function slot: GET is the top 10, GET `&personal=1` your best, POST saves a game only if it beats your best; one document per player in `trustis_scores`). Like Flappy's, the score comes from the browser, so the server can only check it's made of whole numbers and the level fits the lines (a start level of 1–15, plus one every 10 lines). Guests keep a best on the device (`trusty:best:trustis-guideline`).
- **Trusty Fever** (`pages/games/fever.html`) is Curve Fever / Achtung, die Kurve!: up to 6 lines (1–4 people at one keyboard with ←→, A D, J L and the mouse buttons, plus computer players), a crash gives everyone still going a point, and first to 5/10/15 points per opponent, 2 ahead, wins. The rules, power-ups and computer players are in `scripts/fever-engine.js` (pure JS, no DOM, so it runs in Node): `createMatch(setup)` then `update()` 60 times a second, which returns events the page draws from. Collisions use a pixel grid of who drew what; the computers try a few moves ahead and avoid where other heads are about to go. The computers also play behind the start screen. On touch screens player 1 holds the left or right half of the board, or the ◀ ▶ pad under it. A finger can slide between sides, and that counts as a fresh press (square turns need it). The pad has `touch-action: none`, so a held press can never become a scroll, which would cancel it.
- **Trusty Fever online** (the Play online button, shown once the API says rooms are set up): logged-in players make a room or join one by its code or link (`fever.html#room=KXQT`: four letters with no vowels, so codes can't spell words). The host picks the computers, skill, power-ups and length in the side panel (everyone else's is locked), and each person steers their own line with ←→/A D, the board or the pad. Up to 6 people; someone who joins mid-game watches until the next one. Names are site usernames (no made-up nicknames to moderate). The host can also set a **stake** (10/50/100/500 clicks each, with at least 2 people): everyone playing pays it at the click bank before the game starts, or it doesn't start (whoever couldn't pay is told why, everyone else is refunded); the person with the most points takes the pot (computers can't win clicks; a tie splits it); a game everyone playing leaves is called off and everyone's stake comes back.
  - **Why Cloudflare:** Vercel can't keep a room together: its WebSockets close at the function's 5-minute limit on Hobby (games run longer), and two players' connections can land on different instances. So the rooms run in `realtime/`: `worker.js` is a Cloudflare Worker that checks each player's ticket and sends them to one Durable Object per room code, where the whole room lives in memory. The Workers Free plan covers it (about 29 hours of open rooms a day; messages the server sends are free).
  - **The room** (`realtime/room.js`, no platform code, so `tools/local-rooms.mjs` and the tests run the same one) runs the real match from `scripts/fever-engine.js` at 60 steps a second (8x once every person is out, as offline) and decides everything: only the host's `setup`/`start` count, everyone else just sends their steering (`turn` -1/0/1 when it changes, `tap` for square turns). After every step it sends only what changed (`scripts/fever-net.js`: heads in tenths of a pixel, each new piece of line, the engine's other events, players' status when it changes); someone joining partway gets a snapshot with every line drawn so far this round. Every value from a page is checked before it's used (`cleanSetup`), as in the API.
  - **The page** (`scripts/rooms.js` for the connection, the rest in `fever.html`) rebuilds a mirror of the match from those steps and gets the engine's own events back, so `handle()` and `draw()` are the same for local and online games. It plays steps at 60 a second, a step or two behind the newest, and catches up when it falls behind. Online games can't pause: Esc or the pad's Menu button opens a menu while the game goes on, and a hidden tab's line just goes straight. A dropped connection retries 5 times and gets its seat back; the host leaving hands the room to the next person; a room with no game for 15 minutes closes; local records (`trusty:fever:record`) only count games against the computers on this device.
  - **Tickets:** the login cookie is only sent to trustydahorse.com, so the page gets a 60-second ticket from `?action=fever` on `api/leaderboard.js` (`utils/fever-online.js`: POST signs `{ id, name }` for the logged-in player with `FEVER_SECRET`, HMAC-SHA256 in `utils/fever-ticket.js`; GET says where the rooms are, or `null` while `FEVER_ROOMS_URL` or `FEVER_SECRET` isn't set, which hides the Play online button). The Worker checks tickets with the same secret. Blackjack tables use the same tickets.
  - **Versions:** the deployed Worker bundles its own copy of `fever-engine.js`, `fever-net.js` and `blackjack.js`. Bump `PROTOCOL` in `scripts/fever-net.js` whenever a step, snapshot or room message changes shape, and `TABLE_PROTOCOL` in `scripts/blackjack.js` whenever a table message does (a page and a room server that don't match then refuse each other with "reload"), and redeploy the Worker whenever those files or `realtime/` change.
  - **Setup / deploy** (free Cloudflare account): in `realtime/`, `npm install`, `npx wrangler login`, `npm run deploy` (prints the `https://trusty-fever.<subdomain>.workers.dev` address), then `npx wrangler secret put FEVER_SECRET` with a random value of 32+ characters (`openssl rand -hex 32`). On Vercel set the same `FEVER_SECRET` and `FEVER_ROOMS_URL=wss://trusty-fever.<subdomain>.workers.dev`, and redeploy. The Worker reaches the click bank at `SITE_URL` (`[vars]` in `realtime/wrangler.toml`: `https://trustydahorse.com`). Each Durable Object class has its own migration tag in `wrangler.toml` (v1 Fever rooms, v2 Blackjack tables): add a new tag for a new class, never edit an old one. Locally, `npm run dev` in `realtime/` runs the real Worker on port 8790 (secret in `realtime/.dev.vars`, which git ignores) with `SITE_URL` pointed at the dev server's pretend bank on port 8787; start the dev server with `FEVER_ROOMS_URL=ws://localhost:8790` and that `FEVER_SECRET` to use it instead of the local rooms.
- **Trustle** (`pages/games/trustle.html`) is a daily Wordle with Trusty words of 3–9 letters and no server. `scripts/trustle-words.js` lists the answers in the order they're played, one a day from `FIRST_DAY` (Trustle #1), each with an optional `see` link to where the word comes from on the site, shown after the game; after the last word the list repeats in a shuffled order. There are deliberately no hints: they made it too easy. A new word starts at midnight Eastern for everyone (the page corrects a wrong device clock with the site's `Date` header). Only add words at the end, or change ones whose day hasn't come yet: editing today's or an earlier word changes puzzles people already played. `scripts/trustle.js` (pure functions) picks the day's word and grades guesses. A guess must be a Trustle answer or in `data/trustle/<length>.txt`, which were generated from the `wordlist-english` npm package (SCOWL size 70, all four spellings, lowercase a–z only); keep `data/trustle/COPYRIGHT.txt` with them. Each player's games are kept by puzzle number in `localStorage` (`trusty:trustle:history`), and stats/streaks are always worked out from that history (`statsFrom`), so a game synced from two devices never counts twice. When logged in, the page sends its games to `api/trustle-api.js` (POST `{ games }`, answers with the account's whole history; stored in the `trustle` collection) on load, after every guess and when the tab comes back into view; both sides merge with `mergeGame` from `scripts/trustle.js`. After a game, **How everyone did** in the result note opens a dialog counted on the spot from those saved histories (GET `/api/trustle-api?n=<puzzle>`: public, leaves out the asker's own game, skips unfinished and legacy games), so it stores nothing extra. The page adds your own game to its bar in the chart (marked ← you); the lead line and the Players / Win % / Average numbers stay everyone else. Guests' games only live on their device, so only logged-in players are counted. `trusty:trustle:owner` remembers whose games are on the device, so a different account logging in doesn't inherit them. Older saves (`trusty:trustle`, `trusty:trustle:stats`) are converted into history on first load.
  - **Clicks for playing:** a finished game earns 200, 100, 50, 35, 25 or 15 clicks for getting it in 1–6 guesses and 5 for running out (`REWARDS` and `LOSS_REWARD` in `scripts/trustle.js`; the page's side panel lists them too, and `tests/trustle.test.js` checks the two match). `api/trustle-api.js` pays them whenever a logged-in player's synced history holds a finished game it hasn't paid for: it works the amount out from the game itself (`rewardFor`), pays each puzzle once per account (the last 7 paid are `trustleRewards` on the account's `click_game` document, changed in the same atomic update as the clicks, so two tabs or a retried request can't be paid twice) and only within a day of today's puzzle (`rewardable`), so nobody can collect for old puzzles. Its answer adds `rewards` (`{ [puzzle]: clicks }` for those last 7), `added` and the new `clicks` total; the page shows the reward in the result note and tells the header clicker (`announceClicks`) once the last guess has turned over. Guests are told to log in: their games on the device join the account then, so a game from today or yesterday still pays. The words are all in `scripts/trustle-words.js`, so anyone could send a winning game: that's why it's a couple hundred clicks a day at most.
- Arcade games (`driving`, `crazycattle`, `gta`, `football`) wrap iframes behind a click-to-load cover. `pages/games/embed/*` are third-party embed files and are left untouched.

## Backend: `api/` serverless functions (ES modules)

- Each file default-exports `async (req, res)` and branches on `req.method`; some multiplex via `?action=` (`clicks.js`: POST is a click (the day's first also pays the daily bonus), POST `action=tv` for Trusty TV rewards; `leaderboard.js`: `action=profile` for profiles, handled in `utils/profile.js`, `action=rename` for changing your username, handled in `utils/rename.js`, `action=trustis` for the Trustis board, handled in `utils/trustis.js`, `action=admin` for the admin panel, handled in `utils/moderation.js`, `action=update` for the home page's Latest Update, handled in `utils/update.js`, `action=fever` for tickets into the online rooms and tables, handled in `utils/fever-online.js`, and `action=bank` for betting clicks, handled in `utils/bank.js`, and `action=blackjack` for Blackjack on your own, handled in `utils/solo-blackjack.js`; `flappy-api.js`: `action=personal`; `draw-api.js`: `get_leaderboard` / `submit` / `get_personal`, plus POST `action=report` for reporting a drawing, handled in `utils/moderation.js`; `trustle-api.js`: POST syncs a player's games and pays Trustle's clicks, GET `?n=` counts how everyone did).
- **Admin API** (`?action=admin` on `leaderboard.js`, admins only): GET `&view=drawings` (drawing list without images, most reported first), GET `&view=drawing&id=&at=` (one drawing as a PNG, so the list stays small), GET `&view=users` (usernames with their bad-word flags; never emails), POST `{ do: 'remove' | 'dismiss', id, at }`. Reports live on the drawing's `draw_scores` document: `reportedBy` (user ids, so nobody reports twice) and `reports` (open reports; Looks fine sets it to 0). A new high score replaces the drawing and unsets both. Report, remove and dismiss only act if the drawing's `timestamp` still matches `at`, so they can't hit a newer drawing than the one on screen.
- **Vercel's Hobby plan allows at most 12 functions per deployment, and every `.js` file under `api/` counts as one** (11 today). Past 12, every deploy fails, so shared helpers belong in `utils/`, not `api/`.
- **Two separate MongoDB connection helpers — pick the right one:**
  - `utils/db.js` → named export `connectToDatabase()`, uses `MONGODB_URI`, returns the `flappy_scores` db directly. Used for game data (scores, clicks, drawings, leaderboards, profile bios) and the Latest Update.
  - `utils/connect.js` → default export, uses `USERS_MONGODB_URI`, returns `{ client, db }` for the `trusty-users` db. Used by `api/auth/*`.
- Auth: `api/auth/login.js` issues a JWT (`{ userId, username }`, 30 days) in an HttpOnly `authToken` cookie (`setAuthCookie` in `utils/auth.js`), and its GET and POST answers say `isAdmin`. The GET, which `site.js` calls on every page load while logged in, swaps a token with less than 29 days left for a fresh one (`shouldRenew`), so people only get logged out after 30 days away. It also looks up the account's current username, so a token from before a rename is swapped for one with the new name. Protected endpoints call `authenticateUser(req)` from `utils/auth.js`, which returns the decoded payload or `null`; admin endpoints also check `isAdmin(user)` from the same file.
- **Never put a request value into a MongoDB query without checking its type first**: JSON bodies can hold objects, and `{ "$ne": null }` in a query field matches everything (this is how reset-password used to let anyone reset an account). Check `typeof x === 'string'` (or `Number.isSafeInteger`) before the query, as the auth endpoints and `utils/*.js` do.
- **Rate limits** (`utils/rate-limit.js`, counters in the game db's `rate_limits` collection that delete themselves): TrustyGPT allows 40 messages per IP per 10 minutes so nobody can burn the site's Gemini quota; login allows 20 wrong passwords per IP, and 10 per account from one IP, per 15 minutes (the account count goes by IP too, so nobody can lock someone else out by typing wrong passwords at their username); sign-up and reset requests 10 per IP per hour. If the database is down, nothing is limited.
- New passwords need 8+ characters (`passwordProblem` in `scripts/username.js`, used by the sign-up and reset forms and their endpoints); older passwords keep working.
- Password reset emails go through Resend (`api/auth/request-reset.js`) and link to `/pages/auth/reset-password.html?token=…` — keep that path stable. Only a SHA-256 of each token is stored (`utils/reset-token.js`), an account gets at most one email a minute, and the link only points at our own hosts. `api/gemini.js` proxies TrustyGPT to Gemini (`gemini-3.5-flash-lite`, picked for its free-tier daily limit) with Trusty's persona and lore (`PERSONA`) as the system instruction (he only brings up the website when asked: keep site details in their own section of `PERSONA`, or he turns into an ad for it); the chat page sends the whole conversation as `history`, and the function drops the oldest turns past `HISTORY_CHARS`. The Gemini key goes in the `x-goog-api-key` header, never the URL.
