# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Fan site for "Trusty da Horse", a stick-figure horse drawn on notebook paper: static HTML pages (comics, browser games, an AI chat, a 3D viewer) plus Vercel serverless functions backed by MongoDB. There is no build step, bundler, framework, linter, or test suite — `npm test` is a placeholder that fails.

## Running locally

- Deployed on Vercel; `vercel.json` only sets `outputDirectory: "."`, so the repo root is served as-is and every file in `api/` becomes a function at `/api/<path>` (e.g. `api/auth/login.js` → `/api/auth/login`). `404.html` at the root is Vercel's not-found page.
- Full stack: `vercel dev` (needs `.env` with `MONGODB_URI`, `USERS_MONGODB_URI`, `JWT_SECRET`, `GEMINI_API_KEY`, `RESEND_API_KEY`). Frontend only: any static server at the repo root (e.g. `npx serve .`); API-backed features (login, leaderboards, clicker, TrustyGPT) won't work.
- Pages must be served from the root — all asset, script and API paths are root-absolute (`/styles/...`, `/scripts/...`, `/api/...`).

## Shipping changes

- Claude Code sessions push finished work straight to `main` without asking: commit on the session's branch, push it, then fast-forward `main` to it (`git push origin HEAD:main`). If `main` has moved, merge it into the branch first. Never force-push `main`.
- `main` deploys to the live site, so check your change before pushing. There are no tests, so at least load the pages you touched and look for errors.
- This doesn't apply to @claude on GitHub, which only pushes to `main` when explicitly asked (below).

## @claude on GitHub

- `.github/workflows/claude.yml` runs `anthropics/claude-code-action`, pinned to one release commit. Dependabot (`.github/dependabot.yml`) opens a PR when there's a newer one. @claude can't edit workflow files itself.
- Only LukeHorne and csprolesUNCC can start it (the job's `if:`), and it only sees comments from them and itself (`include_comments_by_actor`). To let someone else use @claude, add them to both.
- @claude works on a `claude/issue-N-…` branch and leaves a Create PR link. It only fast-forwards `main` to its branch and pushes it when the person who mentioned it explicitly asks it to push to main. Pushes to `main` deploy to the live site.
- Its pushes go through the action's own `git-push.sh`. Don't add a plain `Bash(git push:*)` or `node` to its allowed tools: the repo is public, issues and PR reviews written by anyone still reach @claude when one of you points it at them, and both can be made to run any command on the runner.

## Frontend architecture

- **Design system:** `styles/stylesheet.css` holds tokens (paper/ink palette, Permanent Marker + Caveat fonts loaded from Google Fonts in each page head) and shared components: `.sheet` (ruled notebook paper), `.card`/`.card-link` (index cards with a stretched title link), `.sticky-note`, `.btn` variants, `.panel`, `.tabs`, `.board` (leaderboard rows), forms, dialogs. `.ink` makes black-on-white line art blend into the paper (`mix-blend-mode: multiply`). `styles/games.css` adds the game shell (`.stage` fixed-aspect play area with `--ar`/`--stage-room`, overlays, focus mode, touch pads) and is only linked from game pages.
- **Viewport heights:** size anything in the page flow (game stages and boards, the TrustyGPT chat box) with `svh`, not `dvh`. On phones `dvh` changes every time the browser toolbar hides or shows, so anything sized with it grows and shrinks while you scroll. `dvh` is right for fixed overlays that cover the screen (dialogs, the mobile menu, the comic reader, focus mode).
- **Shared chrome:** every page loads `scripts/site.js` (ES module) and uses `<trusty-header>` / `<trusty-footer>` custom elements, which render the nav, account area, mobile menu and the header "clicker" (`/api/clicks`). The nav list lives in `NAV` in `site.js`; an entry with `items` is a dropdown group (Trusty Tools: TrustyGPT, 3D Trusty, Trusty Weather, with its own page at `pages/tools.html`) that opens on hover or from its caret button in the header, and is listed indented in the mobile menu.
- **Session:** client login state is the `localStorage` keys `isUserLoggedIn` / `username` (the same keys the site has always used), plus `trusty:admin` for admins. `site.js` only calls `GET /api/auth/login` when the flag is set, clears it on 401, and exposes `session` (`session.isAdmin` only decides whether the header shows the admin link), `sessionReady`, `onSession`, `sessionExpired` (call it when a protected API answers 401), `logout`, `loginHref` (adds a `?next=` return path). `html[data-auth="in"|"out"]` plus `data-auth-show="in|out"` toggles logged-in/out content in markup.
- **Rendering user data:** build DOM with `h()` from `site.js` (never `innerHTML` with API data). Leaderboard names and drawings come from other users; `scripts/leaderboard.js` renders all four boards and only accepts drawings that are PNG data URLs.
- **Modules:** `scripts/leaderboard.js` (fetch/render clicks, Flappy, Draw, Trustis boards + drawing viewer), `scripts/comics.js` (season pages list episodes as cards with `data-episode`/`data-pages`; this turns them into a `<dialog>` reader with `#ep-N` deep links), `scripts/auth.js` (login/register/forgot/reset forms), `scripts/draw-reference.js` (Trusty's reference pose — Draw Trusty grading depends on it), `scripts/game-kit.js` (sprites, ink conversion, sound with a site-wide mute, focus mode, swipe input, local best scores).
- **Adding a comic episode:** drop pages at `images/comics/<comic>/<season>/e<N>/p<M>.jpg` and add an `<article ... data-episode="N" data-pages="M">` card to that season page.
- **Latest Update box:** plain HTML in `index.html` (`.hero-note`); edit it directly.
- **Trusty TV** (`pages/tv.html`, styles in `styles/tv.css`) is a pretend live TV with no server. `scripts/tv-lineup.js` lists YouTube links with their exact lengths and groups them into `CHANNELS` (Trusty TV on 21, SNN on 22, SpongeBob on 23); the channel knob flips through them and the page's `#key` hash picks one, and `scripts/tv-schedule.js` (pure functions) works out from the clock what's airing and how far in, so every viewer sees the same moment. Each run through a lineup is shuffled with a seed from its run number, so the order changes every time but is the same for everyone; when a run starts over, a video never comes back until at least `MIN_GAP` other shows have aired (it can be at most half the lineup, rounded down, not counting one show). The page corrects a wrong device clock with the site's `Date` response header. Logged-in viewers earn 5 clicks for every 5 seconds a show is playing on screen (paused, static and hidden tabs don't count): the page calls `POST /api/clicks?action=tv` with `{ channel: <key> }`, which allows one reward per 5 seconds per account (`lastTvReward`) and adds those 5 seconds to the account's watch time for that channel (`tvSeconds.<key>` in `click_game`, used for the profile's favorite channel), and tells the header clicker through `announceClicks()` in `site.js`. Lengths must be right, or shows get cut off or leave dead air; the page logs a console warning when one is off.
- **Trusty Weather** (`pages/weather.html`, styles in `styles/weather.css`, plus a full-width card at the top of the home page's teasers) is Trusty's local forecast, with no server. `scripts/weather.js` does everything: it only asks for the location from a tap, keeps the rough spot in `localStorage` (`trusty:weather:spot`) so it never asks again, re-detects it silently whenever the browser already allows it, and gets the forecast from Open-Meteo and the town name from BigDataCloud (both free, no key, called from the browser). There's deliberately no way to type or change the location. Trusty's lines are written pools in `weather.js` picked by date, so the home card and the page agree; after sunset he forecasts tomorrow.
- **Profiles** (`pages/profile.html?u=<username>`, styles in `styles/profile.css`; link to one with `profileHref()` from `site.js`) show a user's bio plus stats filled in from game data: member since (`createdAt`, or the `_id` time for old accounts), total clicks + rank, Flappy best + rank, best current-grader Draw Trusty score + rank with the drawing, Trustis best + rank with that game's level and lines, Trustle stats from the synced history (`statsFrom`), and favorite Trusty TV channel (the most `tvSeconds`, with watch time per channel). With no `?u=` it shows your own. Leaderboard names and "Hi, name" in the header link to profiles. The data comes from `utils/profile.js`, served as `?action=profile` on `api/leaderboard.js` to save a function slot: GET `?u=` is public (case-insensitive name lookup, never returns email, `isMe` tells the page to show the edit button), POST `{ bio }` saves your own bio (plain text, max 300 characters) in the `profiles` collection. Snake/Blackjack/Fever bests are only in `localStorage`, so they're not on profiles. Usernames are copied into several collections, so there's no renaming.
- **Admin panel** (`pages/admin.html`, styles in `styles/admin.css`; not in the nav, footer or sitemap) is for the usernames in `ADMINS` in `utils/auth.js` (`carson` and `luke`). They're matched exactly against the name the account was registered with, so someone who signs up as "Carson" isn't an admin. `GET /api/auth/login` and the login response include `isAdmin`; the header then shows an Admin link under the admin's name (the header row has no room for another button) and an Admin panel button in the mobile menu. The page has two tabs. Drawings shows every current-grader Draw Trusty drawing, most reported first, tinted by report count (1, 2–3, 4+), with Remove (takes the drawing and its score off the site, keeping a copy in `removed_drawings` in case it was a mistake) and Looks fine (clears its reports). Usernames shows every username, with the ones containing a bad word (`utils/bad-words.js`) on top; it only flags names, nothing happens to the account. The API is `utils/admin.js`, served as `?action=admin` on `api/leaderboard.js`, and checks `isAdmin` on every request: GET `&view=drawings` (no pictures, since a list of data URLs could pass Vercel's 4.5 MB response limit), `&view=image&id=` (one drawing as a PNG for the page's `<img>`s), `&view=usernames` (never returns emails), POST `{ op: 'remove' | 'dismiss', id, at }`.
- **Drawing reports:** logged-in players can report someone else's Draw Trusty drawing from the drawing viewer in `scripts/leaderboard.js` (on the leaderboards, the Draw Trusty page and profiles), which sends `POST /api/draw-api?action=report` with `{ id, at }`. On the drawing's `draw_scores` document, `reportedBy` keeps it to one report per player and `reports` counts the ones the admins haven't cleared. Looks fine sets `reports` to 0 but keeps `reportedBy`, so the same players can't report it again, and a new high score drawing starts over with none. Drawings are picked out by id plus timestamp (`utils/drawings.js`), so a report or removal never lands on a drawing that replaced the one on screen.
- **Header nav** shows in full from 1120px (1240px when logged in, for the clicker and name); below that it collapses into the menu. Check those widths if you add a nav link.

## Games

- Flappy, Draw, Snake, Trustis, Blackjack and Trusty Fever are self-contained in `pages/games/*.html` (inline module scripts); Trusty Fever's rules live in a module, below. Flappy's physics (800×600 world, gravity, pipe gap/speed/spawn, hitbox) is intentionally identical to the original so leaderboard scores stay comparable — don't tweak it casually. Those constants are per 60 Hz frame, so the simulation runs in fixed 60 steps/second (drawing interpolates between steps) to play the same on 120/144 Hz screens. A pencil scores when Trusty's middle passes its middle (as in Flappy Bird); resting on the floor is safe by design.
- **Draw Trusty grading** lives in `scripts/draw-grader.js` (pure JS, no DOM) and grades against the shapes in `scripts/draw-reference.js`. The browser grades for instant feedback, and `api/draw-api.js` re-grades the submitted PNG (decoded by `utils/png.js`) with the same module and stores its own score, so client-sent scores are ignored. Scores are tagged with `GRADER_VERSION`; leaderboard and personal-best queries only count the current version. If you change grading behavior, bump `GRADER_VERSION` so old and new scores don't mix.
- **Trustis** follows the standard Tetris Guideline: 10×20 field with hidden rows above, 7-bag, SRS rotation and wall kicks, hold, 5-piece next queue, guideline gravity/scoring (T-Spins, back-to-back, combos, perfect clears) and 0.5s lock delay with 15 move resets. The blocks come from `images/sprites.png`; `ART` in the page records which rotation state each drawing was made in (L and J art is vertical), and every cell's sprite turns with the piece so the drawing stays whole. Rotating the O only turns its drawing — it never moves or resets the lock delay, as in standard Tetris. When a logged-in player beats their best, the page sends `{ score, lines, level }` to the Trustis leaderboard (`utils/trustis.js`, served as `?action=trustis` on `api/leaderboard.js` to save a function slot: GET is the top 10, GET `&personal=1` your best, POST saves a game only if it beats your best; one document per player in `trustis_scores`). Like Flappy's, the score comes from the browser, so the server can only check it's made of whole numbers and the level fits the lines (a start level of 1–15, plus one every 10 lines). Guests keep a best on the device (`trusty:best:trustis-guideline`).
- **Trusty Fever** (`pages/games/fever.html`) is Curve Fever / Achtung, die Kurve!: up to 6 lines (1–4 people at one keyboard with ←→, A D, J L and the mouse buttons, plus computer players), a crash gives everyone still going a point, and first to 5/10/15 points per opponent, 2 ahead, wins. The rules, power-ups and computer players are in `scripts/fever-engine.js` (pure JS, no DOM, so it runs in Node): `createMatch(setup)` then `update()` 60 times a second, which returns events the page draws from. Collisions use a pixel grid of who drew what; the computers try a few moves ahead and avoid where other heads are about to go. The computers also play behind the start screen. On touch screens player 1 holds the left or right half of the board, or the ◀ ▶ pad under it. A finger can slide between sides, and that counts as a fresh press (square turns need it). The pad has `touch-action: none`, so a held press can never become a scroll, which would cancel it.
- **Trustle** (`pages/games/trustle.html`) is a daily Wordle with Trusty words of 3–9 letters and no server. `scripts/trustle-words.js` lists the answers in the order they're played, one a day from `FIRST_DAY` (Trustle #1), each with an optional `see` link to where the word comes from on the site, shown after the game; after the last word the list repeats in a shuffled order. There are deliberately no hints: they made it too easy. A new word starts at midnight Eastern for everyone (the page corrects a wrong device clock with the site's `Date` header). Only add words at the end, or change ones whose day hasn't come yet: editing today's or an earlier word changes puzzles people already played. `scripts/trustle.js` (pure functions) picks the day's word and grades guesses. A guess must be a Trustle answer or in `data/trustle/<length>.txt`, which were generated from the `wordlist-english` npm package (SCOWL size 70, all four spellings, lowercase a–z only); keep `data/trustle/COPYRIGHT.txt` with them. Each player's games are kept by puzzle number in `localStorage` (`trusty:trustle:history`), and stats/streaks are always worked out from that history (`statsFrom`), so a game synced from two devices never counts twice. When logged in, the page sends its games to `api/trustle-api.js` (POST `{ games }`, answers with the account's whole history; stored in the `trustle` collection) on load, after every guess and when the tab comes back into view; both sides merge with `mergeGame` from `scripts/trustle.js`. `trusty:trustle:owner` remembers whose games are on the device, so a different account logging in doesn't inherit them. Older saves (`trusty:trustle`, `trusty:trustle:stats`) are converted into history on first load.
- Arcade games (`driving`, `crazycattle`, `gta`, `football`) wrap iframes behind a click-to-load cover. `pages/games/embed/*` are third-party embed files and are left untouched.

## Backend: `api/` serverless functions (ES modules)

- Each file default-exports `async (req, res)` and branches on `req.method`; some multiplex via `?action=` (`clicks.js`: POST `action=tv` for Trusty TV rewards; `leaderboard.js`: `action=profile` for profiles, handled in `utils/profile.js`, `action=trustis` for the Trustis board, handled in `utils/trustis.js`, and `action=admin` for the admin panel, handled in `utils/admin.js`; `flappy-api.js`: `action=personal`; `draw-api.js`: `get_leaderboard` / `submit` / `get_personal` / `report`).
- **Vercel's Hobby plan allows at most 12 functions per deployment, and every `.js` file under `api/` counts as one** (11 today). Past 12, every deploy fails, so shared helpers belong in `utils/`, not `api/`.
- **Two separate MongoDB connection helpers — pick the right one:**
  - `utils/db.js` → named export `connectToDatabase()`, uses `MONGODB_URI`, returns the `flappy_scores` db directly. Used for game data (scores, clicks, drawings, leaderboards, profile bios).
  - `utils/connect.js` → default export, uses `USERS_MONGODB_URI`, returns `{ client, db }` for the `trusty-users` db. Used by `api/auth/*`.
- Auth: `api/auth/login.js` issues a JWT (`{ userId, username }`, 1 day) in an HttpOnly `authToken` cookie. Protected endpoints call `authenticateUser(req)` from `utils/auth.js`, which returns the decoded payload or `null`; `isAdmin(user)` there says whether that user is an admin.
- Password reset emails go through Resend (`api/auth/request-reset.js`) and link to `/pages/auth/reset-password.html?token=…` — keep that path stable. `api/gemini.js` proxies TrustyGPT to Gemini (`gemini-3.5-flash-lite`, picked for its free-tier daily limit) with Trusty's persona and lore (`PERSONA`) as the system instruction (he only brings up the website when asked: keep site details in their own section of `PERSONA`, or he turns into an ad for it); the chat page sends the whole conversation as `history`, and the function drops the oldest turns past `HISTORY_CHARS`.
